# With You 功能清单 PRD

版本：v1.0  
日期：2026-10-24  
适用读者：产品、iOS、端侧 AI、数据、QA  
状态：工程交接草案。功能方向已确认；以下优先级和实施拆分为建议，不代表交付日期或已验证能力。

## 1 范围与优先级

第一版产品范围覆盖语音准备、三段式报告、就诊录音与辅助、离诊理解确认、诊后转录与多模态整理、长期本地健康档案。

| 标记 | 含义 |
| --- | --- |
| P0 | 核心闭环。推荐作为可用首版的必要范围 |
| P1 | 已纳入产品方向，建议在基础闭环稳定后交付 |
| 验证门槛 | 属于目标功能，但具体承诺依赖设备、模型或数据验证；不代表自动删去需求 |

所有优先级均为本次工程化建议。尤其“实时辅助”和“冲突核对”是用户明确希望保留的核心价值；若验证不能满足首发要求，必须明确调整发布范围，不能静默移除或用伪实时界面代替。

## 2 功能清单及验收标准

### A 应用基础与离线

| ID | 功能 | 优先级 | 行为与验收 |
| --- | --- | --- | --- |
| A01 | 语音默认首页 | P0 | 启动后进入圆球入口；点击前不采音；可进入文字和档案，无强制注册或完整病历表单 |
| A02 | 本地资源管理 | P0 | 模型/语言下载、进度、空间检查、失败重试、版本与完整性检查；就绪后离线运行 |
| A03 | 本地持久化 | P0 | Visit、来源、事实和草稿可重启恢复；未完成状态不能显示已完成 |
| A04 | 权限与替代入口 | P0 | 在首次使用时申请麦克风、相机；拒绝权限仍能输入文字或导入文件 |
| A05 | 可理解的状态 | P0 | Listening、Paused、Processing、Needs review、Saved 明确且真实；不只依赖颜色或圆球动画 |
| A06 | 本地数据保护 | P0 | 使用平台安全存储机制保护健康数据和密钥；不得把健康内容写入普通调试日志 |
| A07 | 资源更新 | P1 | 用户主动下载更新；失败后保留可用版本；模型或数据版本可追溯 |

### B 语言和无障碍

| ID | 功能 | 优先级 | 行为与验收 |
| --- | --- | --- | --- |
| B01 | 界面语言 | P0 | 默认跟随系统，支持手动覆盖并持久化；英文设计稿不意味着英文单语产品 |
| B02 | 口述语言识别 | P0，验证门槛 | 在已安装语言范围内识别输入；不确定时询问；不得自动改变整个界面语言 |
| B03 | 患者语言与医生语言分离 | P0 | 患者侧用所选语言，医生展示和报告默认英文；原文可访问 |
| B04 | 文字替代与内容朗读 | P0 | 语音不可用时能打字；摘要、问题、医嘱可朗读，并可暂停 |
| B05 | 低阅读负担与可访问性 | P0 | 每轮一个短问题；主要触控区域建议至少 44pt；适配动态字体和 VoiceOver；大字号时主要操作不被裁掉 |
| B06 | 多语言一致性验证 | P0，验证门槛 | 药名、剂量、单位、否定和时间条件在翻译与朗读中不丢失；支持语言清单须实测确定 |

### C Prepare Visit

| ID | 功能 | 优先级 | 行为与验收 |
| --- | --- | --- | --- |
| C01 | 自由口述与单轮追问 | P0 | 提取已知信息再追问；支持暂停、跳过、纠正和结束，不重复询问已确认事实 |
| C02 | 结构化信息提炼 | P0 | 提取症状、相关记录和患者目标；保留原话、不确定性、来源和状态 |
| C03 | 复用档案 | P0 | 引入相关现有记录供核对；过期或冲突信息不自动当作当前事实 |
| C04 | 问题清单 | P0 | 区分患者提出与 AI 建议；患者可编辑、删除和排序；建议未经选择不默认为患者意见 |
| C05 | 摘要核对 | P0 | Your symptoms、Relevant records、Your questions；可听取、修改、确认；允许带未知项继续 |
| C06 | 固定三段式 PDF | P0 | 上方 Communication summary；下方左 Relevant records；下方右 Questions to ask the doctor；白纸打印版、可选中文本，不使用生成图片充当 PDF |
| C07 | 分享保存打印 | P0 | 本地生成、预览、保存和调起系统分享/打印；取消分享不丢报告；不自动发送 |
| C08 | 报告版本 | P0 | 修改后生成新版本或明确替换；已归档历史报告保持其当时事实快照 |

PDF 细则：默认 US Letter 一页。页头只使用已有身份和预约字段。Relevant records 包含当前用药与补充剂、过敏、既往用药、疾病和近期病史四个子组。问题使用空复选框。适当保留患者用词并以淡桃色强调；来源、时间、反应和未知项可读。不得复制参考图的蓝色编辑选框。超长内容提供明确附页，不静默删掉重要信息。

### D 就诊录音与实时辅助

| ID | 功能 | 优先级 | 行为与验收 |
| --- | --- | --- | --- |
| D01 | 本次录音同意 | P0 | Everyone agreed 默认未选；未确认不能录音；支持无录音模式、撤回和停止 |
| D02 | 录音控制与恢复 | P0 | 开始、暂停、恢复、停止、明确计时；系统中断后保留片段并告知状态 |
| D03 | 本地转录 | P0，验证门槛 | 转录关联音频时间段；听不清或说话人不明保留不确定性；可编辑并保留原文 |
| D04 | 安静的实时追问建议 | P0，验证门槛 | 基于已捕获上下文生成少量问题；支持已问、稍后、忽略；录音运行时不自动播报打断 |
| D05 | Show doctor | P0 | 本机英文大字展示问题；不是分享、不是自动向医生发送消息 |
| D06 | 档案背景核对提示 | P0，验证门槛 | 根据可追溯事实及受支持规则提示待核对问题；能查看原因；不判定处方安全或要求改药 |
| D07 | 广泛药物相互作用校验 | P1，验证门槛 | 仅在本地知识库覆盖并经过验证时启用；显示覆盖不足/无法核对，不把没有结果解释为安全 |
| D08 | 离诊前理解确认 | P0 | 生成讨论内容、用药变化、下一步、未解问题；逐项更正和标记；可未确认结束 |
| D09 | 手动笔记模式 | P0 | 无录音时仍可使用档案、问题、笔记、离诊确认及诊后导入 |

冲突能力边界：语言模型可识别谈话中提及的药物候选、提取上下文和组织问题；不能单独作为药物安全知识来源。药名标准化、过敏匹配、药物相互作用、条件限制是不同能力，需要分别定义数据来源与覆盖范围。未确认药名不得触发确定性的冲突断言。显示“未发现提示”时也不应暗示已全面排除风险。

### E 诊后多模态整理

| ID | 功能 | 优先级 | 行为与验收 |
| --- | --- | --- | --- |
| E01 | 诊后转录与摘要 | P0 | 从录音生成与原文关联的草稿；可重试；不把推测写成医嘱 |
| E02 | 拍照与多页导入 | P0 | 拍摄、重拍、裁边、多页、图片或 PDF 文件导入；原件属于同一 Visit |
| E03 | 本地 OCR 和文档提取 | P0，验证门槛 | 提取药物、医嘱、复诊与检查信息；读不清字段显式待确认 |
| E04 | 来源对比 | P0 | 照片页码与音频片段可回看；来源冲突可选择、纠正或留待确认；原始来源不丢失 |
| E05 | 通俗解释与翻译 | P0 | 患者语言和原文切换、朗读；不新增医嘱，不改剂量或否定 |
| E06 | 行动项 | P0 | 提炼医生已说明的后续安排；未知日期显示待确认，不自动补日期 |
| E07 | 审阅后归档 | P0 | 确认所保存摘要、原件和档案变更；未确认事实保留为草稿；重复保存不重复写入 |
| E08 | 无录音补记 | P0 | 口述回忆、文字或照片可形成记录；标注患者回忆/纸质来源而非医生录音 |
| E09 | 行动提醒 | P1 | 经用户确认后创建本地提醒；首版可仅有行动清单，提醒时区和权限需另定 |

### F 健康档案与管理

| ID | 功能 | 优先级 | 行为与验收 |
| --- | --- | --- | --- |
| F01 | Health Story 概览 | P0 | 无圆球；健康摘要与就诊时间线，Visits / Health 切换 |
| F02 | 健康分类 | P0 | 当前用药、过敏、病史与历史信息分开；明确未填、未知、确认无等状态 |
| F03 | 档案维护 | P0 | 语音、文字、照片新增或更正；保留来源、版本和变更；停药不抹掉历史记录 |
| F04 | 就诊详情 | P0 | 汇总本次 PDF、录音、转录、照片、摘要、问题和确认记录 |
| F05 | 内容导出与删除 | P0 | 明确范围；音频和摘要可分开管理；永久删除前确认，取消操作不改变数据 |
| F06 | 加密备份与恢复 | P1 | 用户主动选择去向；需确定密码/密钥、恢复校验、重复合并策略；不可宣传为已自动云备份 |

## 3 AI 与应用职责

| 组件 | 责任 | 禁止依赖 |
| --- | --- | --- |
| 语音识别 | 音频转文本、时间定位、语言支持 | 不能默认 Gemma 单独完成所有实时语音能力 |
| 对话与提炼模型 | 一次一问、结构化事实、简明解释、提问建议 | 不制造缺失病史、剂量、来源或已确认状态 |
| OCR/视觉模块 | 文档提取、页码与原件关联 | 不自动把低可信文字变成当前用药 |
| 本地参考数据/规则 | 覆盖范围内的可追溯核对 | 不用语言模型记忆替代可靠药物库 |
| 应用业务层 | 权限、同意、状态机、确认、存储与更新 | 模型不能直接改变数据库、分享文件或开启录音 |
| PDF 渲染器 | 将已验证结构化数据排成固定三段版式 | 不使用模型输出的图片作为可打印结构化报告 |

Prepare system prompt 作为可版本管理的独立资源；结构化响应经类型、必填字段、枚举、来源 ID 和状态检查后才能进入报告。非法结构可重试或进入人工编辑，不能静默丢字段。模型版本、prompt 版本和生成记录应关联，便于在本地复现问题。

## 4 建议数据契约

| 对象 | 最少需要保存 |
| --- | --- |
| Visit | ID、阶段、可选预约信息、语言、关联来源、创建和更新时间 |
| Source | ID、类型、本地位置、页码/时间段、原文、处理状态 |
| Fact | ID、类别、值与单位、原话、来源 ID、时间适用范围、确定性、审阅状态 |
| Profile entry | 当前/历史状态、事实引用、变更链、患者确认状态 |
| Question | 内容、患者提出/AI 建议、优先级、患者是否选择、已问/待问状态 |
| Report | Visit ID、结构化快照、PDF 版本、生成时相关模型和 prompt 版本 |
| Action item | 内容、来源、可选已知时间、确认状态，不臆造时间 |
| Consent record | 本次录音关联、用户确认时间、撤回/停止记录；不等同法律认证 |

药物记录需保留商品名/通用名（已知时）、原始字符串、剂量、单位、频率、当前状态；过敏需保留物质和反应。不能只保存一段摘要而丢失这些可核对字段。记录合并采用稳定 ID/来源关联，不能仅凭相似文本覆盖。

## 5 非功能要求与验证门槛

- 离线：资源就绪后，在飞行模式覆盖准备、录音、处理、拍照、档案和本地 PDF。外部分享、打印设备连接和资源下载单独测试。
- 隐私：默认无健康信息上传；崩溃日志不含原始病历、音频、图像、模型输入输出。系统备份是否包含这些文件必须显式设计，不能把“本地处理”误称为“永远不会进入任何备份”。
- 可靠性：分段保存录音，保护草稿；重复请求/重试不导致重复归档；保存完成才显示成功。
- 设备：确定最低 iOS、内存、芯片和可用存储。测试长录音、发热、电量、锁屏、来电与后台中断；具体长录音上限待实测。
- 延迟：收集语音响应、实时建议、OCR、摘要生成耗时分布后制定目标；当前没有已批准的毫秒或秒级承诺。
- 质量：建立多语言测试集，单独测药名、数字、单位、否定、时间、说话人归属、来源定位和无依据新增事实。不能只看摘要“流畅度”。
- 无障碍：动态字体、朗读、VoiceOver、足够对比度、动作文字标签；识别低置信度不只依靠颜色。
- 临床表达：不诊断、不建议自行停药或换药；重要不确定项必须可见。紧急情况的产品文案和行为需专业审阅，不在本 PRD 中定义未经验证的临床规则。

## 6 实施顺序建议

| 阶段 | 范围 | 完成条件 |
| --- | --- | --- |
| 技术验证 | 模型加载、语音/OCR、语言、设备、药物数据 | 有可复现的端侧能力矩阵，明确不支持项 |
| Prepare 闭环 | A/B 基础、C 全部、基本档案 | 口述或文字 → 核对 → 三段 PDF → 本地保存，全程离线 |
| 录音与离诊确认 | D01–D05、D08–D09、E01 | 同意门槛、中断恢复、来源回溯、未确认状态正确 |
| 多模态归档 | E02–E08、F01–F05 | 拍照 → 提取 → 对比 → 核对 → 档案，原件和历史可追溯 |
| 核对与扩展 | D06–D07、资源更新、备份、提醒 | 通过相应数据与性能验证；发布范围显式确认 |

这些阶段用于拆分工程任务，不表示实时辅助可永久省略。

## 7 首版验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| T01 | 患者首次使用、档案空白 | 无需先完成表单，可表达；未知不被写成无过敏 |
| T02 | 已安装资源，开启飞行模式 | 本地准备、处理、档案和 PDF 正常；无隐含云端依赖 |
| T03 | 混合语言且手动指定界面语言 | 对话语言处理正确，界面不擅自切换 |
| T04 | 口述剂量不清、病因不确定 | 摘要与 PDF 保留不确定性，无猜测补全 |
| T05 | 医生不同意录音 | 没有采音；笔记、问题、照片和离诊确认可用 |
| T06 | 录音中断或模型处理失败 | 音频已保存部分可恢复；状态真实；可稍后整理 |
| T07 | 图片模糊、来源冲突 | 可重拍/对比/保留未解决；不自动更新当前用药 |
| T08 | 药物知识库不覆盖 | 显示无法核对，不显示“安全” |
| T09 | 用户只核对部分离诊事项 | 未核对项继续带标记，不显示全部确认 |
| T10 | 报告超长、大字号或长药名 | 无文字裁切；关键事实保留；明确附页策略 |
| T11 | 重复保存、重启后恢复 | 无重复事实或原件丢失，状态一致 |
| T12 | 删除音频、取消分享 | 删除范围与确认一致；取消分享保留本地报告 |

以上为验收设计，不代表已经执行并通过。

## 8 待定决策与不在首版范围

工程启动前需明确：首发语言及机型、各模型/运行时分工、药物参考数据来源与授权/更新、录音长时与后台策略、默认保留期限、系统备份策略、加密备份密钥与恢复交互、临床文案审阅和性能阈值。采用 Gemma 相关模型是当前技术方向，具体模型型号不由本 PRD 锁定。

不默认纳入：自动医院/EHR 同步、家属多账号协作、医生端账户、自动发送给医生、云端健康数据存储、任意语言支持、诊断或处方推荐。新增这些能力需单独需求和数据流设计。
